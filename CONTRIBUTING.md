# Guía de contribución

Para mantener la integridad de este ejercicio académico, sigue estas directrices:

1. **Pruebas como especificación:** Queda estrictamente prohibido modificar o eliminar pruebas existentes en `tests/` para forzarlas a pasar. La suite de pruebas representa la especificación técnica requerida.
2. **Documentación:** Toda función nueva o modificada debe contar con su correspondiente docstring descriptivo en español (argumentos, retornos y excepciones).
3. **Tipado:** Mantener y aplicar anotaciones de tipo (*type hints*) en todas las firmas de funciones.
4. **Historial limpio:** Redactar mensajes de commit claros, concisos y descriptivos según las convenciones comunes (e.g., `fix: corregir manejo de division por cero`).
